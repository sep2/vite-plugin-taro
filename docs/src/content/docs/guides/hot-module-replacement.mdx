vpt 为微信小程序提供基于 Vite、Rolldown 和 React Refresh 的热模块替换（HMR）。

热更新让你在保存代码后立刻看到修改，无需刷新或重新进入页面。当前页面、导航参数、App 数据以及深层 React 组件状态都会尽可能保留，让你可以停留在当前交互位置继续开发，而不必反复导航、填写表单或恢复操作上下文。

## 默认无需配置

默认模板已经启用热更新。如果没有修改模板生成的微信项目设置，不需要添加任何特殊配置，可以直接运行开发命令。

如果项目迁移自其他模板，或曾经修改过微信项目设置，可以确认以下配置：

```ts
vitePluginTaro({
    // ...
    projectConfigJson: {
        // ...
        setting: {
            compileHotReLoad: true,
            urlCheck: false,
            skylineRenderEnable: false
        }
    },
    projectPrivateConfigJson: {
        setting: {
            urlCheck: false
        }
    }
})
```

- `compileHotReLoad` 让微信开发者工具对页面 JavaScript 使用热重载流程。
- `urlCheck: false` 允许运行时向本机 Vite 服务报告补丁交付进度。
- `skylineRenderEnable: false` 保持微信开发者工具的常规渲染调试，因为开发者工具自身的 Skyline 调试暂不支持热更新；这不是 vpt 的限制。

## 可以保留什么

| 状态 | 更新时的行为 |
| --- | --- |
| App 与 `globalData` | App 运行环境不重启，现有数据继续保留。 |
| React 函数组件状态 | React Refresh 边界兼容时，保留 Hook 状态并替换组件实现。 |
| 当前页面身份 | 保留页面路径与参数，并把现有 React 树重新绑定到微信创建的替换页面实例。 |
| 页面渲染树 | 将保留的完整节点树重新同步给替换页面，避免页面短暂变空。 |
| 页面生命周期 | 热更新产生的 `onUnload`、`onLoad` 与 `onShow` 不会再次调用业务处理函数。 |
| 正常页面导航 | 不受热更新拦截，仍按微信和 Taro 的正常生命周期执行。 |

React Refresh 决定组件状态能否安全保留。修改 JSX、样式或事件实现通常可以保持状态；改变 Hook 顺序、把函数组件改成类组件或破坏 Refresh 边界时，React 可能重新挂载组件。

## 更新如何到达小程序

微信开发者工具观察的是磁盘上的小程序项目，而不是浏览器开发服务器。vpt 因此使用物理文件交付更新：

```text
保存源码
   ↓
Rolldown 生成模块补丁
   ↓
dist/wx/hmr/patches.js 更新
   ↓
微信开发者工具重新执行存活页面
   ↓
App 中的模块运行时同步应用补丁
   ↓
React Refresh 更新组件
   ↓
保留的 React 树重新绑定到替换页面
```

每个页面入口都会依赖 `hmr/patches.js`。当这个文件变化时，微信开发者工具会把它识别为页面 JavaScript 更新，并重新执行当前存活页面。补丁在页面继续导入业务模块之前同步完成，因此本次页面执行会直接看到最新模块。

:::note[代码通过文件交付]
更新代码不会通过 HTTP 接口传输。Vite 的本机接口只接收构建标识、补丁序号和重新构建请求等元数据；可执行补丁始终通过 `dist/wx` 中的文件交给微信开发者工具。
:::

## 模块更新与 React Refresh

每次补丁包含发生变化的模块以及它们在模块图中的稳定标识。运行时只处理已经执行过的变更模块：

1. 从变更模块沿已执行的导入方向寻找可接受 HMR 的边界。
2. 收集从变更模块到接受边界之间需要重新执行的模块。
3. 清除这些模块的旧执行缓存。
4. 注册新模块实现并重新执行接受边界。
5. 把最新导出交给上一代边界的接受回调。

尚未执行的延迟模块不需要立即刷新。补丁会更新它的模块实现，首次动态导入时自然执行新代码。

vpt 内置 `@vitejs/plugin-react`，并把它生成的浏览器 Refresh 协议适配到微信全局环境。React 渲染器、Refresh 运行时和组件边界使用同一个全局 Hook，因此不需要在应用中手动编写 `import.meta.hot.accept()`。

## 为什么连续快速保存不会漏更新

补丁使用严格递增的序号，并绑定到一次完整构建的唯一标识：

- 主机保留所有尚未确认交付的补丁。
- 新修改到来时，`hmr/patches.js` 会包含完整的未交付后缀，而不只是最后一次修改。
- 运行时按序应用补丁，重复序号会被忽略。
- 序号中断会停止应用并请求新的完整构建。
- 完整构建会生成新的构建标识，旧页面或延迟请求携带的补丁无法污染新构建。

运行时确认某个序号已经到达后，主机才会释放对应补丁。即使连续保存速度快于微信开发者工具处理速度，下一次文件交付仍会补齐缺失更新。

## 什么时候会执行完整构建

HMR 只在能够找到安全接受边界时应用。以下情况会自动退回完整构建：

- Rolldown 判断当前模块图变化无法表示为补丁。
- 已执行模块向上找不到接受边界。
- HMR 传播遇到无法安全处理的循环路径。
- 补丁序号缺失、模块工厂缺失或补丁执行失败。
- React Refresh 边界主动使本次更新失效。

完整构建会重新生成磁盘输出、轮换构建标识并清空旧补丁。终端会打印要求完整构建的原因；不需要在业务代码中处理补丁失败。

## 页面状态为什么能够保留

微信开发者工具交付页面 JavaScript 更新时，会创建替换页面并重放页面生命周期。默认 Taro 行为会在 `onUnload` 卸载 React 树，再在 `onLoad` 创建新树，组件状态也会随之消失。

补丁到达后，vpt 会把这一次生命周期标记为热更新产生的替换过程：

1. `onUnload` 保存现有页面路径和参数，但不卸载 React 树。
2. `onLoad` 把原页面身份恢复到替换页面实例。
3. 保留的页面节点重新绑定新的微信页面实例。
4. 完整节点树重新同步，确保替换页面立即得到当前 UI。
5. 首次 `onShow` 结束热更新窗口，不重复执行业务 `onShow`。

这套处理只覆盖补丁交付引起的合成生命周期。用户返回、跳转、关闭页面等真实导航仍调用原有生命周期。

## 样式更新

浏览器 Vite 会通过 DOM 注入或替换 `<style>`，微信小程序没有这套机制。开发构建会直接更新磁盘中的 WXSS，微信开发者工具负责重新加载样式文件。

样式更新不需要在模块运行时中创建或删除 style 节点，也不会因为浏览器式样式注入而重建 React 树。全局样式、Tailwind 输出和组件样式都遵循相同的磁盘更新流程。

## 排查问题

### 保存后没有更新

检查以下项目：

1. 当前运行的是 `dev:wx`，而不是生产构建或 H5 开发服务。
2. 微信开发者工具打开的是当前项目生成的 `dist/wx`。
3. `compileHotReLoad` 已开启，`urlCheck` 已关闭。
4. Vite 进程仍在运行，并且终端没有构建错误。
5. 没有开启微信开发者工具的 Skyline 渲染调试。

### App 状态被重置

查看终端是否提示执行了完整构建。模块边界失效、配置变化或补丁应用失败都会轮换构建标识并重建 App。

### React 组件状态被重置

即使本次更新使用 HMR，React Refresh 仍可能判断组件无法安全保留状态。检查 Hook 顺序、组件导出结构和组件类型是否发生变化。

### 本机报告请求失败

确认微信开发者工具没有拦截本机 HTTP 请求，项目配置中的 `urlCheck` 为 `false`，并检查代理或防火墙是否阻止开发者工具访问 Vite 打印的本机地址。
