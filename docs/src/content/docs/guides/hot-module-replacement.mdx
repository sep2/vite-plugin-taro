`create-vite-taro` 模板已经启用小程序开发者工具热更新，无需额外配置。

## 使用

按目标选择开发命令（`wx` 为微信，`zfb` 为支付宝）：

<Tabs syncKey="package-manager">
    <TabItem label="npm">

```sh
npm run dev:wx
npm run dev:zfb
```

    </TabItem>
    <TabItem label="pnpm">

```sh
pnpm dev:wx
pnpm dev:zfb
```

    </TabItem>
    <TabItem label="bun">

```sh
bun run dev:wx
bun run dev:zfb
```

    </TabItem>
</Tabs>

等待构建完成，在微信开发者工具中打开 `dist/wx`，或在支付宝小程序开发者工具中打开 `dist/zfb`。

保存 JavaScript、TypeScript、React 组件或样式后，当前开发者工具会自动显示更新。

## 选择热更新模式

`devtools`（微信默认，无需配置）：通过开发者工具重新注册 Page 并保留应用和页面状态，更新更快、开发运行时更小。

```ts
hmr: {
    mode: 'devtools'
}
```

`interpreter`（支付宝目前唯一支持的模式）：通过解释器在当前 App 中执行更新并保留状态，不重新注册 Page，但更新更慢、开发运行时更大。

```ts
hmr: {
    mode: 'interpreter'
}
```

`rebuild`：每次有效源码变化都重新生成完整原生项目并重启 App，不保留运行状态。

```ts
hmr: {
    mode: 'rebuild'
}
```

## 不需要热更新时：修改后自动重新构建

如果不需要热更新或保留运行状态，例如让 AI 批量修改代码时，也可以使用 Vite 原生的 `--watch`，在文件修改后自动重新构建：

<Tabs syncKey="package-manager">
    <TabItem label="npm">

```sh
npm run build:wx -- --watch
npm run build:zfb -- --watch
```

    </TabItem>
    <TabItem label="pnpm">

```sh
pnpm build:wx --watch
pnpm build:zfb --watch
```

    </TabItem>
    <TabItem label="bun">

```sh
bun run build:wx --watch
bun run build:zfb --watch
```

    </TabItem>
</Tabs>

这会运行 `vite build --watch`，在源码变化后重新构建 `dist/wx` 或 `dist/zfb`，并重启应用，不保留运行状态，适合批量修改代码的场景。

监听构建会保留输出目录，并使用稳定的入口、依赖和资源文件名。每轮构建先写完依赖、分包和原生配套文件，再原子更新带有构建标识的 `app.js`，通知开发者工具重新加载完整产物；不会通过反复改写 `app.json` 来触发刷新。编译失败时不会发布新的 App 入口。

不要在开发者工具仍打开项目时手动删除输出目录。监听期间可能保留已经不再引用的旧文件；正式发布前应运行不带 `--watch` 的构建，该路径仍使用正常的目录清理和内容哈希文件名。

区别在于：`build:wx --watch` / `build:zfb --watch` 默认打包的是生产版本，而 `dev:wx` 下的 `hmr.mode: 'rebuild'` 打包的是开发版本。监听构建不启用 Vite 开发服务器的 HMR 协议，也不会保留 React 状态。

:::note
使用 `build:wx --watch` 时，必须设置 `projectConfigJson.setting.compileHotReLoad: false`，否则微信开发者工具可能刷新异常；切回 `dev:wx` 时恢复为 `true`。
:::

## 保留的状态

普通热更新会保留：

- App 和 `globalData`；
- 当前页面及其参数；
- 兼容更新下的 React Hook 状态；
- 页面中的输入内容。

热更新产生的页面替换不会重复调用业务 `onUnload`、`onLoad` 和 `onShow`。正常跳转、返回和重新进入页面时，生命周期仍照常执行。

改变 Hook 顺序、组件类型或导出结构时，React 可能重新挂载对应组件并重置它的局部状态。

## 以下微信配置会影响热更新

`create-vite-taro` 模板已经包含以下设置：

```ts
projectConfigJson: {
    setting: {
        compileHotReLoad: true,
        urlCheck: false,
        skylineRenderEnable: false
    }
},
projectPrivateConfigJson: {
    setting: {
        urlCheck: false
    }
}
```

`compileHotReLoad: true` 开启开发者工具的热重载。补丁文件变化后，开发者工具只重新加载受影响的页面，不重启整个小程序；vpt 依靠这个行为保留 App 和 React 状态。

`urlCheck: false` 关闭开发者工具的服务器域名校验，让小程序可以连接本机 Vite WebSocket 并报告热更新结果。它只影响开发者工具中的调试连接，不会放宽正式版小程序的服务器域名限制；`rebuild` 模式不需要该连接。

据[微信官方说明](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/skyline/migration/compatibility.html#常见的兼容问题)，开发者工具的 Skyline 调试模式暂不支持热更新。日常开发时保持 `skylineRenderEnable: false`；检查 Skyline 效果时再临时开启。参见[Skyline 模式](/guides/skyline-mode/)。

## 状态何时会重置

以下情况会重新启动应用：

- 使用 `rebuild` 模式保存任意有效源码变化；
- 点击开发者工具的“编译”；
- 重启 `dev:wx` / `dev:zfb` 或修改 Vite 配置；
- 补丁模式中的某次代码变化无法安全热更新，vpt 自动执行完整构建。

## 保存后没有更新

依次检查：

1. `dev:wx` 或 `dev:zfb` 仍在运行且终端没有构建错误；
2. 开发者工具打开的是当前项目对应的 `dist/wx` 或 `dist/zfb`；
3. 微信已开启 `compileHotReLoad` 并关闭 `urlCheck`，支付宝已开启 `enableHMR`；
4. 微信调试时 `skylineRenderEnable` 未开启。

仍然无效时，关闭开发者工具和开发命令，删除 `dist/wx` / `dist/zfb`，重新运行 `dev:wx` / `dev:zfb` 后再打开生成目录。

实现细节参见[热更新实现原理](/references/hmr-implementation/)。
