`create-vite-taro` 模板已经启用微信热更新，无需额外配置。

## 使用

启动微信开发模式：

<Tabs syncKey="package-manager">
    <TabItem label="npm">

```sh
npm run dev:wx
```

    </TabItem>
    <TabItem label="pnpm">

```sh
pnpm dev:wx
```

    </TabItem>
    <TabItem label="bun">

```sh
bun run dev:wx
```

    </TabItem>
</Tabs>

等待构建完成，在微信开发者工具中打开 `dist/wx`。

保存 JavaScript、TypeScript、React 组件或样式后，开发者工具会自动显示更新。

## 保留的状态

普通热更新会保留：

- App 和 `globalData`；
- 当前页面及其参数；
- 兼容更新下的 React Hook 状态；
- 页面中的输入内容。

热更新产生的页面替换不会重复调用业务 `onUnload`、`onLoad` 和 `onShow`。正常跳转、返回和重新进入页面时，生命周期仍照常执行。

改变 Hook 顺序、组件类型或导出结构时，React 可能重新挂载对应组件并重置它的局部状态。

## 以下微信配置会影响热更新

`create-vite-taro` 模板已经包含以下设置：

```ts
projectConfigJson: {
    setting: {
        compileHotReLoad: true,
        urlCheck: false,
        skylineRenderEnable: false
    }
},
projectPrivateConfigJson: {
    setting: {
        urlCheck: false
    }
}
```

`compileHotReLoad: true` 开启开发者工具的热重载。补丁文件变化后，开发者工具只重新加载受影响的页面，不重启整个小程序；vpt 依靠这个行为保留 App 和 React 状态。

`urlCheck: false` 关闭开发者工具的服务器域名校验，让小程序可以向本机 Vite 服务报告热更新结果。它只影响开发者工具中的调试请求，不会放宽正式版小程序的服务器域名限制。

据[微信官方说明](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/skyline/migration/compatibility.html#常见的兼容问题)，开发者工具的 Skyline 调试模式暂不支持热更新。日常开发时保持 `skylineRenderEnable: false`；检查 Skyline 效果时再临时开启。参见[Skyline 模式](/guides/skyline-mode/)。

## 状态何时会重置

以下情况会重新启动应用：

- 点击开发者工具的“编译”；
- 重启 `dev:wx` 或修改 Vite 配置；
- 某次代码变化无法安全热更新，vpt 自动执行完整构建。

完整构建是热更新无法继续时的正常恢复方式，终端会显示相应提示。

## 保存后没有更新

依次检查：

1. `dev:wx` 仍在运行且终端没有构建错误；
2. 开发者工具打开的是当前项目的 `dist/wx`；
3. `compileHotReLoad` 已开启，`urlCheck` 已关闭；
4. `skylineRenderEnable` 未开启。

仍然无效时，关闭开发者工具和开发命令，删除 `dist/wx`，重新运行 `dev:wx` 后再打开生成目录。

实现细节参见[热更新实现原理](/references/hmr-implementation/)。
