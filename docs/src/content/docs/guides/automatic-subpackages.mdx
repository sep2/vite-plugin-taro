使用 vpt 时，启动时需要的代码照常使用 `import`，希望惰性加载的功能则使用 `import()`。vpt 会自动把相关模块安排到主包或分包，并生成所需的微信配置。

`import()` 只控制加载时机，不指定分包名称或目录。一个功能的模块可能分布在多个分包中，多个功能也可能使用同一个分包；模块之间始终使用标准 `import`，无需关心它们最终位于哪里，使业务代码与微信分包完全解耦。

## 优势

### 业务代码与分包位置解耦

源码不包含主包名称、分包名称或生成目录。功能大小、共享依赖或最终分包布局发生变化时，不需要修改导入路径。

### 模块可以跨包引用

模块之间继续使用普通静态 `import`。一个分包中的模块可以引用主包、当前分包或其他分包中的模块，vpt 会处理物理加载和执行顺序。

### 共享依赖不会重复打包

每个模块只有一个物理归属。多个按需功能使用同一依赖时，vpt 不会为了满足分包引用而为每个功能复制一份。

### 无需维护分包配置

vpt 根据最终构建结果生成 `app.json.subPackages`。不要在 `appJson` 中手动配置 `subPackages` 或 `subpackages`。

## 创建加载边界

### 动态导入

使用 `import()` 延迟加载一个功能：

```ts
async function openReport() {
    const { createReport } = await import('./features/report')
    return await createReport()
}
```

如果 `./features/report` 只在动态边界之后使用，它会参与分包规划。若它同时被启动代码静态导入，则仍然属于主包；业务代码在两种情况下都正常使用 `await import()`。

### `React.lazy`

React 组件可以直接使用 `lazy()`：

```tsx
import { lazy, Suspense } from 'react'
import { View } from 'virtual:taro/components'

const Report = lazy(() => import('./features/report'))

function ReportEntry() {
    return (
        <Suspense fallback={<View>正在加载报表…</View>}>
            <Report />
        </Suspense>
    )
}
```

`./features/report` 需要默认导出 React 组件。首次渲染 `<Report />` 时会触发动态导入。

## 表达加载策略

| 目标 | 写法 | 结果 |
| --- | --- | --- |
| 启动时必须可用 | 从 App、页面或其静态依赖中 `import` | 保留在主包 |
| 按需加载功能 | 仅通过 `import()` 到达 | 参与分包规划 |
| 分阶段加载 | 在按需功能内部继续使用 `import()` | 创建下一阶段加载边界 |
| 仅引用 TypeScript 类型 | 使用 `import type` | 构建时移除，不影响分包 |

### 启动依赖优先

只要模块可以从 App 或页面沿静态导入到达，它就会留在主包。其他按需功能可以直接复用它，不会生成副本。

检查公共入口和聚合导出，避免从启动路径重新导出本应按需加载的大型功能：

```ts
// 这会让 editor 成为启动依赖
export { mountEditor } from './features/editor'
```

### 围绕完整功能创建边界

适合按需加载的内容通常是低频功能、大型编辑器、图表、报表或导出工具。不要逐个动态导入很小的工具模块，应围绕完整业务功能创建边界：

```ts
async function openEditor() {
    const { mountEditor } = await import('./features/editor')
    return mountEditor()
}
```

### 分包位置由 vpt 管理

vpt 不提供手动指定分包名称、目录或模块清单的选项。一个动态边界不对应一个固定分包；vpt 可以合并较小的功能，也可以把大型依赖图拆到多个分包。

静态导入关系也只是模块尽量放在一起的参考，不是强制同包规则。位于分包 A 的模块，其静态依赖可以最终位于主包、分包 A 或分包 B。

位置规划算法、跨分包加载方式和微信运行时原理参见[模块系统](/vite-plugin-taro/references/module-system/)。

## 当前范围

全自动位置规划目前只管理 JavaScript 模块。全局 `app.wxss`、图片、字体和其他构建资源暂不参与规划；对这些资源的自动规划已列入后续版本，敬请期待。
