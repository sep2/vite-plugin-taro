vpt全自动分包让你只需要关心功能何时加载。你不再需要手动决定模块应放入主包还是某个分包，也不需要按体积反复调整分包目录。

在需要按需加载的位置使用 JavaScript 动态 `import()` 即可。vpt 会自动安排代码、控制分包大小并生成最终配置，无需维护 `app.json.subPackages`。

## 优势

:::note[模块自由引用]
模块之间可以自由引用，无论引用方和依赖最终位于主包、同一分包还是不同分包，都不需要修改导入方式或关心跨包方向。
:::

### 接近标准 Web 的模块行为

业务代码继续使用标准 ESM 的 `import` 与 `import()`。vpt 会尽可能保持标准 Web 的模块行为，并自动处理代码的物理位置与加载顺序：

- **主包到分包**：动态 `import()` 会在需要时加载对应代码。
- **分包到主包**：分包模块可以直接引用主包模块。
- **分包到分包**：不同分包中的模块可以直接相互引用。

不需要为了适配微信原生分包的引用方向而复制共享模块、创建中转文件或修改导入路径。

### 共享依赖不会重复打包

[旧版 Taro 的“智能提取分包依赖”方案](https://docs.taro.zone/docs/mini-split-chunks-plugin)会把多个分包共同使用的模块提取为 `sub-common`。由于微信原生分包不能跨分包引入文件，这些模块需要复制到每个相关分包，Taro 文档也明确提示这会增大整体包体积。

vpt全自动分包为每个模块确定唯一归属，不再需要为了满足分包引用限制而复制依赖。

### 分包位置对业务代码透明

模块的导入路径不包含主包或分包目录。即使功能大小、动态入口或最终分包布局发生变化，源码仍然保持普通 Web 项目的组织方式。

## 创建加载边界

### 动态导入

使用 `import()` 延迟加载一个完整功能：

```ts
async function openReport() {
    const { createReport } = await import('./features/report')
    return await createReport()
}
```

调用 `openReport()` 时，对应功能及其专属依赖才会加载。代码不需要调用微信分包 API，也不需要知道生成的分包路径。

### React.lazy

React 组件可以直接使用 `lazy()`：

```tsx
import { lazy, Suspense } from 'react'
import { View } from 'virtual:taro/components'

const Report = lazy(() => import('./features/report'))

function ReportEntry() {
    return (
        <Suspense fallback={<View>正在加载报表…</View>}>
            <Report />
        </Suspense>
    )
}
```

`./features/report` 需要默认导出 React 组件。首次渲染 `<Report />` 时，对应功能才会加载。

## 分包策略

应用通过静态 `import` 和动态 `import()` 控制加载时机，vpt 再根据这些边界决定模块归属与物理分包。

| 目标 | 写法 | 结果 |
| --- | --- | --- |
| 启动时必须可用 | 从 App、页面或其同步依赖中静态 `import` | 保留在主包 |
| 按需加载完整功能 | 只通过动态 `import()` 到达 | 功能及其专属依赖成为分包候选 |
| 分阶段加载 | 在延迟功能内部继续使用动态 `import()` | 创建下一阶段加载边界 |
| 仅引用 TypeScript 类型 | 使用 `import type` | 构建时移除，不影响模块归属 |

### 主包所有权优先

只要存在一条从 App 或页面同步到达模块的静态引用路径，该模块就会留在主包。延迟功能仍可直接复用它，不会生成副本。

检查公共入口和聚合导出，避免从同步路径重新导出本应延迟加载的大型功能：

```ts
// 不要在同步入口中重新导出延迟功能
export { mountEditor } from './features/editor'
```

### 围绕业务功能创建边界

适合延迟加载的内容通常是低频页面、大型编辑器、图表、报表或导出工具。不要逐个动态导入很小的工具模块，应围绕完整业务功能创建边界：

```ts
async function openEditor() {
    const { mountEditor } = await import('./features/editor')
    return mountEditor()
}
```

延迟模块也可以在顶层使用 `await import()`，依赖会在该模块初始化时按需加载：

```ts
// features/report.ts
const { exportToPdf } = await import('./report-pdf')

export function exportReport() {
    return exportToPdf()
}
```

:::caution[主包不支持顶层 await]
微信要求 App、页面和组件在启动时同步完成注册，因此主包的同步依赖图必须立即执行完成。顶层 `await` 会让模块初始化变成异步过程，主包无法等待它完成。请只在完全位于动态 `import()` 边界之后的模块中使用顶层 `await`。
:::

### 物理分包由 vpt 管理

vpt 不提供手动指定分包名称、根目录或模块清单的选项。一个动态导入边界不保证对应一个物理分包：较小的功能可以合并，过大的依赖图也可以拆到多个分包。

你只需要表达同步或按需加载关系，vpt 会负责分包数量、大小和引用要求。

## vpt 如何规划

每次构建时，vpt 会按以下顺序生成分包：

1. 将 App、页面及其同步依赖保留在主包。
2. 收集只能通过动态 `import()` 到达的 JavaScript 模块。
3. 优先把同一功能及相互依赖的模块放在一起。
4. 在规划大小内合并较小功能，或拆分过大的延迟依赖图。
5. 为每个模块确定唯一归属，并生成稳定的分包目录。

单个分包的规划预算为 **1,900,000 字节**，为构建生成代码预留微信 2 M 限制内的空间。

:::caution
规划大小根据转换后的 JavaScript 估算，不等于微信开发者工具最终统计的上传体积。发布前仍应使用微信开发者工具或 CI 检查最终包体积。
:::

生成的目录使用稳定哈希命名：

```text
dist/wx/
├── app.json
└── sub/
    ├── p_2f8a91c4/assets/<content-hash>.js
    └── p_b14e638a/assets/<content-hash>.js
```

相同模块图会得到相同的 `p_<8位哈希>` 根目录，被 tree shaking 删除的代码不会留下空分包。

vpt 会同步生成 `app.json.subPackages`：

```json
{
    "subPackages": [
        {
            "name": "p_2f8a91c4",
            "root": "sub/p_2f8a91c4",
            "pages": []
        }
    ]
}
```

这些分包只存放 JavaScript，因此 `pages` 为空。不要在 `appJson` 中手动配置 `subPackages` 或 `subpackages`，vpt 会根据当前模块图生成最终声明。

## 当前范围

- 全自动规划的对象是 JavaScript 模块。
- 全局样式仍输出到主包的 `app.wxss`。
- 图片、字体和其他构建资源仍由主包管理。
- 异步分包加载需要微信基础库 2.11.2 或更高版本。

然后检查：

1. `dist/wx/app.json` 中是否出现生成的 `subPackages`。
2. `dist/wx/sub/p_*/assets` 中是否存在按需加载代码。
3. 首次触发对应 `import()` 时，微信开发者工具是否加载分包。
4. 微信开发者工具的包体积是否满足发布限制。

新增或移除动态导入边界后，如果需要确认新的物理布局，请重新启动 `dev:wx`。
